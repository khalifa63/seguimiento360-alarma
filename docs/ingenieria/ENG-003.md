# ENG-003 — Versionado y trazabilidad

Estándar de ingeniería para identificar fuentes, builds, revisiones y aceptación sin confundirlos con el estado instalado.

## Identidades independientes

| Identidad | Convención |
| --- | --- |
| Sistema integrado | SemVer, etiqueta propuesta system/vX.Y.Z |
| Firmware por componente | SemVer, etiqueta por componente/vX.Y.Z |
| Fuente | Commit Git completo |
| Build | ID único, no reutilizable; vinculado al commit y hash SHA-256 |
| Electrónica | Revisión independiente, por ejemplo HW-R001 |
| Mecánica | Revisión independiente, por ejemplo CAD-R001 |
| Manual | SemVer independiente, asociado a revisiones compatibles |
| Instalación | Registro privado por equipo; nunca inferir del HEAD |

Las etiquetas se crean solo sobre fuentes publicadas, sin mover etiquetas previas. La versión mayor indica incompatibilidad de contrato, menor funcionalidad compatible y parche corrección compatible. Para revisiones físicas, cualquier cambio de ajuste o interfaz requiere revisión de compatibilidad. No asignar versiones históricas sin evidencia.

## Manifiestos públicos

SYSTEM_MANIFEST.yaml y COMPATIBILITY.yaml, formato 2. Mantener valores desconocidos como null. La matriz distingue la integración de cámara del enlace ESP-NOW; no certifica un protocolo inexistente. Los IDs de evidencia son referencias no sensibles, no datos privados.

El validador verifica estructura, cobertura, referencias, formato de hashes y condición de aprobación. No verifica autenticidad de artefactos, existencia de un commit remoto, evidencia física ni secretos arbitrarios. La aprobación exige revisión humana y pruebas reales; no basta editar YAML.

Ejecutar en entorno aislado con Python 3.12 y PyYAML 6.0.2:

```bash
python scripts/check_manifests.py
python -m unittest discover -s tests -p test_check_manifests.py -v
```

GitHub Actions ejecuta estos controles en PR relevantes, sin acceso a hardware.

## Registros privados y recuperación

Aplicar [versionado y flasheo](../infraestructura/versionado-y-flasheo.md) y [registros privados](REGISTROS_PRIVADOS.md). Conservar herramientas, hashes y tamaño del artefacto, configuración mediante alias no secreto, resultado y fecha UTC. No publicar binarios privados ni sobrescribir un release. La restauración requiere respaldo correspondiente, identidad verificada y autorización.

La implementación de builds de todos los nodos y del instalador queda en ENG-004 o etapas de validación. El historial físico no se fabrica retrospectivamente.
