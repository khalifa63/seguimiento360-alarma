# ENG-010 — Integración y aceptación

Plan de aceptación de una versión integrada, separado de certificación comercial.

## Puertas de salida

| Puerta | Evidencia exigida | Estado inicial |
| --- | --- | --- |
| Fuentes | Commits publicados y revisión | Pendiente |
| Builds | Artefactos identificados y verificados | Pendiente |
| Hardware | Revisiones y pruebas de banco | Pendiente |
| Compatibilidad | Matriz con resultados reales | Pendiente |
| Infraestructura | Seguridad, recuperación y monitoreo | Pendiente |
| Usuario | Instalación, alertas y manuales aprobados | Pendiente |
| Operación | Mantenimiento, respaldo y retiro | Pendiente |

## Escenarios de integración

Vincular nodos al HUB; verificar cada evento hasta portal y actuador esperado. Probar pérdida de energía, Wi-Fi, backend, reinicio y duplicados en entorno aislado. Verificar aislamiento de usuarios y restauración. No generar alarmas reales sin coordinación.

## Liberación

Registrar resultados y riesgos residuales, resolver bloqueantes, aprobar versión exacta con responsable y evidencia. Actualizar manifiestos solo después de pruebas. No declarar aptitud comercial, normativa ni seguridad a partir de CI.

Pendiente ejecución física, acceso operativo y aprobación humana.
